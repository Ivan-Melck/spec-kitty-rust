## Measured defects (red-first, through the real public service)

F-1 — nested `repr()` printability. `python_json::python_repr` classified with Rust
`char::is_control()` (Unicode `Cc` only), so nested strings CPython escapes were emitted
verbatim and changed the commit subject (and therefore the commit object). Measured with the
live pinned `ProfileInvocationExecutor._commit_op_record` on real temporary repositories:

| nested profile/action fixture | pinned source subject | source `repr` |
| --- | --- | --- |
| `{"k":"a\u00a0b"}` | `op({'k': 'a\xa0b'}): x [...]` | `\xa0` (Zs) |
| `{"k":"a\u200bb"}` | `op({'k': 'a\u200bb'}): x [...]` | `\u200b` (Cf) |
| `{"k":"a\u2029b"}` | `op({'k': 'a\u2029b'}): x [...]` | `\u2029` (Zp) |
| `["a\u00adb","\ue000","\u0378"]` | `op(['a\xadb', '\ue000', '\u0378']): x [...]` | Cf / Co / Cn |
| `{"\u00a0":1}` / action `["\udbff\udfff","\ud834\udd73"]` | `op({'\xa0': 1}): ['\U0010ffff', '\U0001d173'] [...]` | key Zs; astral Cn / Cf |

Oracle facts (`/tmp/sk-unicode-probe.root/json-surrogate-facts.log`): CPython `3.11.15`,
`unicodedata.unidata_version == "14.0.0"`, **969,596** non-printable code points in **701**
contiguous ranges over `U+0000..=U+10FFFF` (Cc 65, Zs 16, Cf 163, Cn 829,834, Zl 1, Zp 1,
Cs 2,048, Co 137,468). U+0020 printable; U+007F/U+0080/U+00A0/U+00AD use `\xNN`;
U+200B/U+2028/U+2029 use `\uNNNN`; U+1D173/U+E0001/U+10FFFF use `\UNNNNNNNN`; every
surrogate is non-printable.

F-2 — lone and non-paired surrogate escapes. `legacy_json` refused them because
`LegacyValue::String` was a Rust `String`. Measured source behavior:

| raw row (unused field / nested) | pinned source |
| --- | --- |
| `"unused":"\ud800"`, `"\udc80"`, `"\udc00"` | commits `op(p): a [...]` |
| `"unused":{"\ud800":1,"\ud800":2}` (surrogate keys) | commits |
| `"unused":"\ud800\u0041"` | commits (two code points) |
| `"unused":["\ud800\ud800\udc00","\ude00\ud83d"]` | commits |
| `{"profile_id":["\ud800","\udc80"],...}` | commits `op(['\ud800', '\udc80'])` |
| `{"profile_id":{"\ud800":1},...}` | commits `op({'\ud800': 1})` |
| `"\ud800\uZZZZ"` / `"\ud800\u00"` / `"\ud800\udc0"` | `json.loads` invalid `\uXXXX` |
| `"\ud83d\ude00"` | one astral scalar, equal to raw `😀` |
| `"\ud800\udc00\ud800"` | `[U+10000, U+D800]` |
| `"\ud800\ud800\udc00"` | `[U+D800, U+10000]` (greedy pairing) |
| `"\ude00\ud83d"` | two lone units, order retained |

Decoded duplicate-key semantics are code-point equality: `{"\ud83d\ude00":1,"😀":2}` is one
key (first position, last value); `{"\ud800\u0041":1,"\ud800A":2}` is one key; `"\ud800"` and
`"\ud83d"` stay distinct.

## Correction (one authority per concept)

1. `python_json::python_repr_codepoints(&[u32])` is now the **single** `repr` formatter;
   `pub fn python_repr(&str)` is a thin wrapper over it (no second/third formatter).
   Escaping mirrors CPython `unicode_repr`: `\t \n \r` short forms, chosen quote and `\`
   escaped, printable kept, otherwise `\xNN` `<0x100`, `\uNNNN` `<0x10000`, `\UNNNNNNNN`.
2. New private `python_unicode` module: verified CPython 3.11.15 `str.isprintable()` data as
   701 sorted, disjoint inclusive ranges, with a binary-search `is_printable(code)`. Data
   is generated by the new development-only `scripts/rust/generate_python_repr_unicode.py`,
   which first runs `scripts/rust/verify_oracle.py` against the lock-exact interpreter and
   refuses on missing/drift; `--check` fails if the committed table differs from a fresh
   verified generation (reproducible, rustfmt-stable output). No runtime Python, no new
   dependency, no registry/serde/feature change.
3. `legacy_json::PythonString` stores Python code points (`Vec<u32>`), so lone surrogate
   units are preserved; object keys and duplicate detection compare code points; nested
   `repr` goes through the canonical formatter, which escapes surrogates so the rendered
   message is always valid UTF-8. `PythonText` carries Python `str(value)` (verbatim top-level
   string, or `repr`/`unknown`) up to one fallible UTF-8 conversion point. Grammar
   validation, numeric decoding, integer digits and the 1000-frame operational guard are
   untouched.
4. `op_commit` changed only the bottom wiring: `started_field` returns `PythonText`; the
   message is composed as `op(<profile>): <action> [<8>]` with a fallible UTF-8 step acted
   on after the skip/branch decisions and before `SafeCommitRequest`. The reference's
   protection refusal happens inside its `safe_commit`, which the UTF-8-only seam cannot
   reach (residual 3). A used surrogate refusal names the code point and never claims
   `Invalid invocation record`.

## Measured residuals — not fixed, not claimed

1. **UTF-8-only commit-message seam (explicit request).** Source-used `\udc80..\udcff`
   **commits**: POSIX argv uses `surrogateescape`, the git process receives the raw byte
   (`0x80`/`0xff`; `source-argv-bytes.log`) and git stores the message as valid UTF-8
   `C2 80` / `C3 BF` (`op(\u{80})` / `op(\u{ff})`), with a `did not conform to UTF-8`
   warning. Native refuses truthfully because `sk_git::SafeCommitRequest` takes
   `String`/`&str`. Reproducing this needs an explicit byte-message seam in `sk_git`
   (message bytes plus its validation, not a UTF-8 re-encode); it is **requested, not
   implemented**, and not silently broadened here.
2. **Exception wording/classification (F5).** Source refuses a used `\ud800` or
   `\udc00..\udc7f` with `UnicodeEncodeError(…)`; native refuses with a truthful
   "not representable as UTF-8 (code point U+…)" message. Both refuse and no commit lands.
3. **Decision precedence and mutation on failure (F5).** A skip decision still wins in both
   (test `legacy_used_surrogate_keeps_source_decision_order` part a). On a protected branch,
   source refuses on protection before encoding, while the native message must already be
   UTF-8 before `safe_commit`, so the native refusal is the encoding one (part b, measured).
   Source also leaves the record **staged** (`M  kitty-ops/…`, `--cached` non-empty,
   `source-index-mutation.log`); native returns before `safe_commit` and leaves
   HEAD/index/status/refs/records untouched. This is a direct consequence of residual 1.
4. F5 broader Git byte-message boundaries and the shadow-branch/F5 work remain separate, as
   do executor/CLI/StepContract/protected-main/workflow/platform/performance claims. No
   blanket parity is asserted: only the F-1/F-2 string/repr semantics measured above.
5. This is not arbitrary-JSON equivalence and not a doctrine Unicode casefold/word-category
   closure; it is `repr` printability data plus code-point-preserving decode.
