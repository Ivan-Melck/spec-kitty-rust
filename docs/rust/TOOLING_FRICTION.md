# Rust rewrite tooling notes

- Subagent model selection required the exact provider-qualified catalog id, `tokenfactory/deepseek-v4.1-flash-1017`; no alternate model was substituted. Async completion notifications, rather than task polling, drove integration.
- Rust was absent from the VM. Rustup installed the minimal toolchain; the repository now pins 1.99.1 with formatter and Clippy components. The declared compiler floor matches the tested release line.
- The shared VM has other workloads. Agent crate checks and coordinator aggregate checks use `CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0`; final aggregate evidence is coordinator-owned. Current work uses the existing target only (the first historical kernel build used an external target). Concurrent scoped builds reproduced rustdoc `E0463: can't find crate for tempfile` after 228 native Git tests passed. Serialize the **entire** Cargo invocation, including tests/doctests, with `flock /tmp/spec-kitty-rust-cargo.lock env CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 cargo …`; do not relabel that failed run a clean aggregate.
- Changing the declared Rust minimum from an untested 1.85 to 1.99 enabled additional Clippy suggestions (notably let-chains). These were fixed in code, not suppressed; aggregate tests, Clippy and formatting were rerun.
- Green initial unit tests missed FIFO opens that block before metadata checks, an escaping asset-directory anchor, and a complete non-LF event tail. Independent review and real-process regressions found these classes; the common I/O boundary was unified rather than patching only the CLI.
- The account initially had an older public fork, 6,097 commits behind the first fetched baseline. The operator later authorized fast-forwarding fork `main`; it first matched upstream `8ffeb0180`, then was fast-forwarded and remotely rechecked at `7c50fd38b`. The rewrite still uses behavior baseline `9aed3a80` pending the now-641-commit semantic reconciliation; neither history was rewritten.
- Pack trees are pinned upstream artifacts, not committed content in this checkout. Charter inspection refuses missing declared roots. Fetching packs is a separate upstream build-tooling/network action; no Rust command silently fetches or invokes Python.
- From a temporary CWD, checker tests require both the repository and `src` on `PYTHONPATH`: `PYTHONPATH="$repo:$repo/src"`. Omitting the first causes the five oracle-verifier tests' `scripts.rust` import to fail; it is not a product test pass. The corrected environment reproduced all 54 checker/oracle tests.
- The installer lock-contract test's process-group termination coincided with repeated harness cancellations. It already called `process_group(0)`, so the exact causal signal path was not proven. Cleanup now uses a native single-process helper, an explicit READY handshake and direct child kill/reap; the contention/release test completes without cancelling the harness. Do not restore negative-PGID signalling or treat the earlier interrupted runs as passes.
- Repeated T3 restarts cancelled a coordination implementation after partial writes, including an unfinished planning rewrite. A cancelled task is not a delivery. Read its recorded activity and current bytes before redispatching; preserve partial work and inspect pending commands before repeating mutations. Duplicate completion notifications refer to the same reviews, not additional evidence.
- The first frozen aggregate counted an init oracle test that returned early when an optional override was absent. A new subprocess regression reproduced the false pass; init now shares the required, lock-exact oracle selector and verifies explicit overrides. The corrected aggregate is 1,947 passes/0 failures/8 parent-exercised helpers, with all three init post-states actually compared. Do not reuse the earlier 1,946 count as init conformance evidence.
- An intermittent installer lock re-acquire failure was not resolved by repeated green runs. A deterministic duplicated-descriptor regression showed that close-only release could retain a flock beyond the guard. Explicit owning-PID unlock fixes that mechanism; independent review accepts it. This is descriptor simulation, not real-fork evidence or proof of the earlier failure's cause.
- Planning approach and remaining work are maintained in `STATUS.md`; design decisions in `DECISIONS.md`; verification and review dispositions in `VERIFICATION.md`. These artifacts describe the delivered foundation, not a claim that the full rewrite is finished.
